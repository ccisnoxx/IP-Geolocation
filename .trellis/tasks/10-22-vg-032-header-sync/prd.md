# VG-032 请求头同步恢复

2026-10-22 用户明确授权恢复必要 DNR 权限，先处理旧规则残留与迁移，再实现按站点的 Accept-Language 与页面语言同步并做真实 Chrome 验证。VG-023、024、028 依赖均 done；VG-031 候选保留 review，不代替人工验收。

## 合同

- 仅恢复 declarativeNetRequestWithHostAccess，沿用现有 host scope；不增加常规 DNR、反馈、webRequest 或 debugger 权限。
- 随包默认启用高优先级静态 allow 隔离，覆盖已知旧规则；在解除隔离前清理两个规则存储中的历史 1001、1002、1100..2099 并读回验证，范围外规则保留。
- 2026-10-22用户补充明确授权：已核验头规则改为dynamic持久投影（40000..49999），首次接管须确认新范围无未知占用；旧session30000..39999独立迁移。所有配置迁移、修复、变更的快照及写回占同队列，写影响头投影的配置前先持久隔离。config-model/resolver仍为唯一事实源，local仅记录所有权版本；稳定冷启动不重复隔离。
- 普通 HTTP(S) 导航按目标域的有效页面语言；子资源按 initiator 域的有效页面语言，覆盖跨源资源。更具体启用规则即使关闭语言，也排除父规则。
- 语言按列表顺序生成下降 q 权重；不支持用任意字符串注入 HTTP 头。
- 页面 userScripts 和请求头在同一配置队列对账，请求头依赖页面注册成功；请求头故障保留隔离、撤销新请求头规则并报告部分同步，既有语言/时区能力独立继续运行。不声称跨两个 Chrome API 原子提交。同步期间和旧文档/BFCache 保留快照的窗口不保证一致，已有文档须完整重建。
- Worker/SharedWorker 的 JavaScript 语言仍原生；不能将请求头一致性扩展为所有 realm 的语言恢复。

## 验证

- 单元及集成覆盖迁移漏项、隔离读回失败、范围外保留、权重/域名与子域排除、页面失败撤销新规则、串行保存、权限失败与恢复。
- 隔离临时 Chrome profile 和 loopback 合成站点：升级前预置旧规则，升级后后台清理前观测隔离；迁移、顶层/iframe/跨源子资源、新旧文档、禁用、后台停止唤醒与更新。
- 完整本地门禁、独立只读复核；真实 Chrome 实际版本及证据范围如实记录。仅 review，不提交发布。

- 冷启动验证须使用正常UI安装的独立有界面profile，完整退出观测进程树后再启动，不reload扩展、不startWorker、不发管理消息；先采首HTTP inline及实际头，再只读核验。覆盖配置写后、规则提交前中断及用户脚本开关关闭的恢复边界。
- 补充自动恢复旧HTTP标签的启动验证：正常设置“继续浏览上次打开的网页”，仅保留一个活动测试标签；不传启动网址/强制恢复参数，在CDP连接前由服务器关联首导航响应和首inline自报，日语及切换德语后各完整退出重启一轮。稳定设置结论不扩展到开关变化、多窗口、延迟标签或崩溃恢复。
