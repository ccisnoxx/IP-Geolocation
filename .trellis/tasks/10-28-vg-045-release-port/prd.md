# VG-045 release/1.3.1 代码迁移

用户明确要求合入功能代码，而非仅接入提交历史。以 `57d42df` 为实现基线，逐项移植 `5b61905` 的有效代码及测试；不整份覆盖独立架构。

## 授权与顺序

2026-10-28 用户授权以下四阶段，随后明确选择第4阶段以 release 分支行为为目标逐项制定迁移。

1. languages 稳定引用、德国/中国/纽约预设、配置体检、故障角标、真实DOM测试。
2. Date 本地解析及 setter、固定字体别名、自然缺失字体回退；页面与既有 Blob 链同步。
3. 批量出包、验证矩阵、原生形状对照、独立环境启动器、Lint 与覆盖率。普通包和 persona 包分别验证。
4. queryLocalFonts、三层字体、fonts.check、定位形状与权限、自动出口跟随、热更新、扩大 Worker 范围。每项先明确行为、迁移和验收；禁止将分支包装路径直接等同浏览器支持。

依赖 VG-040、VG-042 当前均为 done；VG-043/044 仍为 review，本任务不替代其人工验收。现行权限、配置、注入及暂停边界在对应第4阶段合同明确实施前继续适用。

## 适配要求

- 配置归一化、解析和持久化仍由现有唯一所有者负责；保存、修复、导入都走现有串行事务。
- 保留 strict/compatible、Date 子类、字体单次转换/重入/恢复、DNR 命名空间与隔离事务等现有有效合同。
- 配置体检区分非法数据、未解析信号和语义提示；禁用开关及 native/consistency 预设不自动判为错误。
- 字体和定位策略变化、权限及新数据流必须同步文档与验证；不得只改显示或测试预期。
- 工具仅管理本次创建的进程和临时目录；不复制宽泛进程清理、不使用缺少期望值的恒真校验。
- Node/VM/jsdom、dry-run、实际浏览器与发布验收分别记录。版本、tag、Release 不由功能迁移自动触发。

## 验收

每阶段提供实际差异和定向证据；最终完整类型检查、单测、构建及差异检查通过。新增合同具有现实正负例、迁移或往返证据；真实浏览器未运行或未覆盖项明确记录。本地实现验证后为 review，人工验收后才可 done。
